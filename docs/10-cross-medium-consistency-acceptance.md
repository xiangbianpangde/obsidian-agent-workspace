# 论文工作台 P0 · 跨介质一致性验收标准（Acceptance: Cross-Medium Consistency）

> 裁决日期：2026-09-22
> 裁决者：项目负责人（用户）
> 依据：独立评审 13 轮（会话 `01a0aeaf`）的性质层面论证
> 对应 ADR：[ADR-010](../architecture/ADR/ADR-010-cross-medium-consistency.md)

---

## 一、为什么需要这份文档

P0 完成前的最后 13 轮评审反复围绕同一类问题：**Vault 文件与 SQLite 之间无法原子写入**。评审逐步收紧，最终给出性质层面的结论：

> 「读 → 检查 → 提交」无论把检查放得多近，检查与提交之间总存在窗口。事务内 callback 也只是把窗口推后，不是关闭它。

这个问题**没有"再修一层就闭合"的终点**，必须由负责人裁定验收标准。本文档固化该裁定，作为 P0 的验收依据，并防止后续重复走同一条死路。

## 二、裁决：A —— 检测 + 收敛

**不追求任一时刻的严格一致；追求「不一致必然被检出，且必然由权威源收敛」。**

### 2.1 必须成立的五项（可验收）

| # | 要求 | 对应探针 |
|---|---|---|
| A1 | 写入前记录**决策依据**的摘要作为 CAS 前置条件；Manifest 已偏离则拒绝写入，外部编辑必须保留 | `test_p0_w`、`test_p0_w2` |
| A2 | 提交前若偏离已可见，事务回滚（不落下不一致绑定） | `test_p0_y`、`test_p0_y2` |
| A3 | **提交后必须复读**：若 Manifest 在提交窗口内移动，返回 `post-commit-drift` 且 **intent 保持 pending**，**不得**报 `completed` | `test_p0_z` |
| A4 | 下一次 index 必须把 SQLite 收敛到 Manifest（权威方向恒为 Manifest → SQLite） | `test_p0_z2` |
| A5 | 无法证明来源的 intent（无 published digest）必须 fail-closed（`unverifiable`），不得凭路径猜测 | `test_p0_v` |

### 2.2 明确允许（不视为缺陷）

- **提交窗口内的短暂不一致**（毫秒级，仅当外部编辑恰好落在该窗口）；
- **pending intent 长期存在**：这是**待收敛信号**，不是错误，运维不得当作故障清除；
- UI 在下一次 index 前短暂显示 SQLite 旧值。

### 2.3 明确禁止（违反即 NO-GO）

1. **只移动检查位置**就宣称闭合（把检查从提交前挪到提交内）——窗口只是变窄，不是关闭；
2. **用 SQLite 反向覆盖 Vault** 来"消除不一致"——方向颠倒，会丢用户编辑；
3. **把 `post-commit-drift` / pending 当作 clean completed**——必须保持可见。

## 三、为什么不选 B（严格瞬时一致）

选项 B 要求覆盖**所有写者**的跨进程文件锁。但写者包括：

- 工作台进程 —— 可约束；
- **用户用 Obsidian 直接编辑** —— 不可约束；
- 未来的同步工具 —— 不可约束。

要消除窗口，只能在检测到外部编辑时拒绝或回滚**用户的编辑**。这与 ADR-006 的核心前提「Vault 是用户的知识资产，可被 Obsidian 直接编辑」直接冲突——用一个内部一致性目标锁住用户对自己笔记的编辑权，代价不可接受。

**结论：严格瞬时一致在"允许外部编辑"的前提下不可达。这不是实现缺陷，是架构约束。**

## 五、13 轮评审中被证伪的指控

为完整性记录：评审员在压力测试中提出 3 条指控经复核为**误报**（他读取的是旧输出），并已主动撤回：

1. `_recover_rename_source` 二次 read 的 TOCTOU；
2. `update_manifest` 未传 `expected_manifest_digest`；
3. 同一处的重复指控。

**同时有 7 处被证实为真实缺陷**（含"全新数据库下 source 从不落库"、"UTF-8 边界误判导致论文降级"、"digest 记录写前而非写后导致正常崩溃现场卡死"），均已修复并加变异验证。

## 六、验收结论

按本文档 §2.1 的五项要求，P0 的跨介质一致性验收标准**已定义并已实现**，对应探针全部通过（426 项测试全绿）。

后续若 P1 引入新的写者（如 AI 自动写入），必须重新评估本文档 §3 的写者集合——**新增写者若不受约束，A 的短暂不一致窗口会相应变宽**。
