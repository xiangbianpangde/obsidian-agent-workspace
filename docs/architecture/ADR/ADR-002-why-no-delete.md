# ADR-002: 为什么系统层全局禁止删除文件 (Why No Delete)

- **状态**: Accepted
- **日期**: 2026-09-02
- **决策者**: 用户 & Sol (GPT-5.6 Sol High)

## 背景与问题
在大多数 CRUD Web 应用中，Delete 是标配操作。然而本工作台面向的是用户的真实本地知识库（拥有多年的学术研究、复习笔记与项目日志）。知识资产的误删除或被恶意脚本/异常并发误删，将产生不可逆的灾难性损失。

## 决策内容
我们在**系统代码层与 API 契约层全局禁止删除文件**：
1. 后端代码中完全不存在任何 `delete_file()` 函数；
2. FastAPI 路由中不暴露任何 `DELETE /api/file` 端点，任何 HTTP DELETE 请求均被 404/405 拦截；
3. 对于由于外部（如用户手动在 Finder 或 Obsidian 中）删除的文件，文件系统监听器（Watchdog）仅在 `index_events` 审计表中记录 `deleted` 墓碑事件，工作台自身绝对不主动调用文件删除操作；
4. 任何对笔记的编辑保存操作，保存前均在 `data/backups/` 目录下自动生成只读快照备份。

## 收益与代价
- **收益**：从根本上消除误删用户核心资产的可能性，达到极高的数据安全防护水平。
- **代价**：若用户确实想清理无用笔记，须回到本地文件管理器或 Obsidian 客户端中执行。
