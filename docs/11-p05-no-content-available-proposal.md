# P0.5 提案：无内容可读状态（No Content Available）

> 提案日期：2026-09-22
> 状态：**待立项**（评审裁定 B 类不纳入已完成的 P0 闭环）
> 来源：P0 结项时发现 17 篇论文夹仅有元数据占位文件
> 关联：ADR-006（合法 Paper 的最低条件）、ADR-010（跨介质一致性）

---

## 一、问题的发现过程

P0 结项、处理评审要求的「47 篇待确认项」时，我最初把它们当作同质问题统计。逐篇核查后发现是**两类不同性质**的内容，我此前的统计疏漏了这一点：

| 类别 | 篇数 | 内容性质 | 处置 |
|---|---|---|---|
| A 类 Deepsearch 系统解析 | 15 | 3–6 KB 实质分析（榜单成绩、技术架构） | ✅ 已采纳（语义正确） |
| B 类 `00-元数据.md` | 17 | 正文为「PDF 与全文翻译**尚未获取**——付费墙」 | ⏸ 保持不采纳 |
| 多候选（2–4 文件） | 15 | 需人工排序主次 | ⏸ 保持待确认 |

**B 类的真实状态不是「来源待确认」，而是「尚无内容可读」。** 这是 P0 状态机没有表达的语义。

## 二、为什么不能强行纳入现有状态

评审明确裁定当前保持不采纳是**正确的安全处置**，并给出三条硬约束：

1. **不得绑为 `TRANSLATION_FULL`** —— 会把「我们还没有这篇论文」当作论文正文展示在阅读器里；
2. **不得创建/变更 Manifest 身份** —— 会为「尚无内容」的目录锚定一个永久身份；
3. **不应伪装成 `DEGRADED`** —— `DEGRADED` 的语义是「**已有权威绑定但文件缺失**」，与「从未有内容」是不同的事实。

三条约束在提案前已实测确认成立（见 §5）。

## 三、提案内容

### 3.1 引入独立的 discovery reason

在现有 `BindingState.AMBIGUOUS` 之外，为「目录中只有元数据占位、无任何可读来源」引入独立语义：

- 候选名：`NO_CONTENT_AVAILABLE`（或 `CONTENT_UNAVAILABLE`）；
- 与 `AMBIGUOUS` 的分流依据：**是否存在至少一个可读来源**。
  - 有 ≥1 个可读候选，但主次不明 → `AMBIGUOUS`（需人工消歧，走 `resolve`）；
  - 只有元数据占位、无任何可读来源 → `NO_CONTENT_AVAILABLE`（需获取文献，**禁用 `resolve`/`adopt`**）。

### 3.2 判定信号（需确认是否可靠）

当前可用的判定信号（需 P0.5 实现时确认其稳健性）：

- 目录内仅存在 `00-元数据.md`，且其正文包含「尚未获取」「未获取全文」「付费墙」等占位标记；
- 该文件不属于任何可读来源角色（既非 PDF，也非翻译/解析产物）。

**风险**：以文件名 + 文本标记判定属于启发式。P0.5 需决定用显式标记（如 frontmatter 字段）还是保持启发式，并明确误判的 fail 方向。**倾向 fail-closed**：判定不确定时退回 `AMBIGUOUS`（可由人工处置），而非宣称「无内容」（会阻止人工采纳）。

### 3.3 交互与统计

| 面 | 要求 |
|---|---|
| UI 状态 | 独立徽章，语义为「需获取 PDF/全文」，**不与「待确认」混用** |
| UI 操作 | **禁用** resolve / adopt；展示已有的元数据（标题、作者、DOI、获取渠道） |
| 统计 | 在论文列表中**单列**，不计入「待确认」计数 |
| 扫描器 | 当前会为它创建 1 个候选来源（`role=OTHER_MARKDOWN`、`is_candidate=True`、`active=True`）。候选不参与绑定与健康判定，因此现状安全；P0.5 需决定是否保留该候选以供 UI 展示元数据 |

### 3.4 明确不做

- 不自动联网获取文献（违背零出站边界，ADR-009）；
- 不自动创建 manifest；
- 不改动 P0 已冻结的状态机语义（`AMBIGUOUS` / `ADOPTED` / `DEGRADED` / `RESOLVED` / `PDF_ONLY` / `DUPLICATE_ID_CONFLICT` / `INACTIVE`）。

## 四、范围与顺序

- **不扩张本轮 P0**，**不回滚当前启用**（评审明确要求）；
- 立项为独立 P0.5，在 P0 结项后单独排期；
- 需先确认 §3.2 的判定信号，再决定是否实现。

## 五、当前状态的实测确认（提案前提）

在写本提案前已核查：17 篇全部满足评审的三条约束。

| 约束 | 实测结果 |
|---|---|
| 未绑为 `TRANSLATION_FULL` | ✅ 无 active 非候选来源 |
| 未创建/变更 Manifest 身份 | ✅ 无 `paper.workbench.json` 文件 |
| 未伪装成 `DEGRADED` | ✅ 状态均为 `AMBIGUOUS` |

核查方式：按**目录路径**遍历（非按 `paper_id`——删库重建后 ID 会重分配，按 ID 核查会得到虚假的「row missing」）。
