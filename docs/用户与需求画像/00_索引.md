## 0. 一分钟速览

| 维度 | 事实 |
|---|---|
| 身份 | 人工智能专业大学生（中南民族大学），康怡琳课题组方向 |
| 工作方式 | 日常用 pi / Codex 等 Agent 开发；Obsidian 管理学习、研究、项目 |
| 用户已有体系 | 个人 Wiki + 日记 + 模板系统 + Agent 工作流（含 AI 秘书、签名 broker、AI Memory） |
| 已有治理契约 | [`docs/governance/AGENTS.md`](../governance/AGENTS.md) —— Vault 治理的操作性合同（分区权限 + 写面隔离） |
| 核心痛点 | **知识孤岛** —— Obsidian（知识沉淀）/ Agent（任务执行）/ IM（外部信息）三者之间缺少统一工作入口 |
| 项目定位 | 在 Obsidian 之上做增强层，**不替代 Obsidian**；把个人知识库变成人和 Agent 可共同操作的 Personal Knowledge Workspace |
| 终局目标 | Obsidian Workspace + Agent System + Message System + Task System = **Personal AI Operating System** |

**需求一句话**：把自己的本地知识资产、Agent 会话、即时消息、课程与作业统一到一个本地优先的工作台里，为将来接入 AI 分析预留数据层。

## 2. 用户已拍板的决策（L2 要点）

完整记录见 [`docs/03-decisions-and-questions.md`](../03-decisions-and-questions.md)。摘要：

1. **先文档后代码** —— Deliverable 1 = 技术方案 v0.2（开发合同）；Deliverable 2 = Demo 实现。
2. **vault 路径不写死** —— 走 `config.yaml`，未来支持多 vault。
3. **Template 兼容三层** —— L1 纯变量（P0）；L2 `tp.file.move` 转 `create_target_path`；L3 Obsidian Plugin 桥接（不做）。**JS 执行明确禁止**。
4. **数据模型需扩展** —— 除 files/tags/file_tags/metadata 外，加 Vault Intelligence Layer 与 AI Memory 建模。
5. **新增验收项** —— 2300+ md、首次扫描 <30s、增量更新、标签统计、PARA 分类、模板变量替换、代码层无 `delete_file()`。

### 用户提出的环境冲突（要求 Sol 裁决）
> v0.1 说「编辑允许、删除禁止」，但 AGENTS.md 治理契约把大部分目录定为只读。
> 直接「全局编辑」违反既有治理 → v0.2 必须给出**写能力矩阵**。

**这条冲突演变出的关键不变量**：工作台的写权限不是「能写就写」，而是**镜像用户既有的治理分区**。详见 [ADR-004](../architecture/ADR/ADR-004-permission-model.md) 与 [ADR-002](../architecture/ADR/ADR-002-why-no-delete.md)。

### 三个跨领域不变量（由需求/治理衍生）

1. **零删除**（ADR-002）—— 源自用户「Vault 是核心知识资产」的判断。
2. **零出站**（ADR-009）—— 源自用户「本地优先，数据不上云」。
3. **不替代 Obsidian**（ADR-001）—— 源自用户既有工作流（Obsidian 是主入口）。

## 5. 用户的工作上下文（影响需求的环境事实）

### 5.1 用户已建的治理体系（最关键的外部约束）

用户在 Vault 中已有一份**完整的治理契约**（[`docs/governance/AGENTS.md`](../governance/AGENTS.md)），定义了分区权限与写面隔离。这不是我的设计，而是**用户的现存事实**，工作台必须镜像而非绕过：

| 区域 | 默认权限 | 写面 |
|---|---|---|
| `03. 🟤 表达 Present/个人 Wiki/` | **仅签名 broker** | `wiki-write-broker` + Secure Enclave 签名 + 一次性 nonce |
| `01. 🟣 采集 Grasp/Wiki 研究草稿/` | 只读/dry-run（apply 策略暂停） | — |
| `01. 🟣 采集 Grasp/任务/秘书inbox/` | 受控本地写 | `./tools/secretary-capture-inbox` |
| `01. 🟣 采集 Grasp/任务/秘书记忆/` | 受控本地写 | `./tools/secretary-memory-review` |
| `01. 🟣 采集 Grasp/任务/每日任务/` | 读 + 用户确认后写 | outline→plan 展开 |
| 日记正文 | **默认只读**，追加需人机签名 | 人机签名 broker（Touch ID/系统密码） |
| `.obsidian/` `credentials` `attachments` `.trash/` | **永不读取/永不索引** | — |

**对工作台的直接含义**：用户方案原文里的「编辑允许」在现实中是不成立的 —— 大部分目录受治理约束。这就是 [ADR-004](../architecture/ADR/ADR-004-permission-model.md) 写能力矩阵的来源，也是工作台扫描器必须有排除清单的原因。

### 5.2 其他环境事实

| 事实 | 对需求的影响 | 来源 |
|---|---|---|
| Vault 约 2300+ md（勘测时），三层结构（根 / 8 方向 / 论文夹）；**当前已增至 3617** | 必须有索引 + 有界分页，不能全量加载 | [`docs/01-vault-survey.md`](../01-vault-survey.md) |
| 大部分目录受 AGENTS.md 治理约束（只读/broker/签名） | 需写能力矩阵，不能「全局编辑」 | [`docs/03-decisions-and-questions.md`](../03-decisions-and-questions.md) |
| 模板是 Templater DSL（JS 块、日期偏移、move 路由） | 「替换变量」太粗糙 → 三层降级 | 同上 |
| AI Memory 已有 registry（Claude 53 / Codex 65 条，状态机） | 需建模或只读化 | 同上 |
| 真实 Vault 文件名含中文、全角冒号、emoji、NFD/NFC 差异 | 所有 API 用不透明 ID，绝不用路径做 key | [ADR-009](../architecture/ADR/ADR-009-pdf-viewer-and-zero-egress.md) |
| 用户在其他会话并行工作，Vault 有未提交改动 | 工作台不得触碰用户的 git 状态 | 本项目实践约束 |

## 8. 本目录的维护约定

- **不复制原文**：本目录只做定位与溯源，避免同一事实两份（杜绝不一致）。
- **新增画像材料时**：优先追加到本索引的对应章节，而非新建散落文件。
- **与 `HANDOFF.md` 的关系**：HANDOFF 是**运行状态**交接；本目录是**需求与人的画像**，变动频率低。
- **权威性**：本目录是**导航**，不是权威来源。任何冲突以 §1 表格中的 L1/L2 原文为准。
